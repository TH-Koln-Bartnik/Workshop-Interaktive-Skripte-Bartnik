9b — Ohne GitHub: das Skript direkt in Moodle

Was Sie nach diesem Kapitel können

  • Ihr gerendertes Skript in RStudio als ZIP-Paket packen und als Material „Datei“ in einen Moodle-Kurs stellen, Schritt für Schritt und ohne GitHub,
  • ein einzelnes KI-Lernspiel als HTML-Datei in Moodle bereitstellen, wenn Sie kein ganzes Skript brauchen,
  • mit Buch und H5P ein interaktives Skript ganz innerhalb von Moodle bauen und abwägen, wann dieser Weg der bessere ist.

Worum es im Kern geht

Kapitel 9 bringt Ihr Skript ins offene Netz. Viele Lehrende wollen aber gar nicht ins offene Netz. Sie wollen, dass ihre Studierenden das Skript dort finden, wo auch der Rest des Kurses liegt: im Moodle-Kurs hinter dem Login. Dafür brauchen Sie weder ein GitHub-Konto noch Git. Es genügen RStudio, mit dem Sie das Skript ohnehin bauen, und Ihre Rechte als Lehrperson in Moodle.

Der Grund, warum das funktioniert, ist einfach. Was Quarto in den Ordner docs/ schreibt, ist eine vollständige Webseite aus gewöhnlichen Dateien: HTML für den Text, CSS für das Aussehen, JavaScript für die Spiele. Diese Webseite braucht kein Programm auf einem Server, sie läuft in jedem Browser. Moodle kann solche Dateien ausliefern wie jede andere Webseite.

Dieses Kapitel stellt drei Optionen vor, geordnet nach dem, was die meisten Teilnehmenden nach dem Workshop brauchen:

Drei Wege in den Moodle-Kurs ohne GitHub.
Option Was Sie brauchen Was Studierende sehen Zeit beim ersten Mal
1 Skript als ZIP-Paket RStudio, die Workshop-Vorlage das ganze Skript mit Navigation, Suche und Spielen 20 Minuten
2 Einzelnes Lernspiel ein KI-Chat ein Spiel auf einer eigenen Seite 10 Minuten
3 Buch und H5P nur Moodle ein Moodle-Buch mit H5P-Übungen, bewertbar 1 Stunde und mehr
HinweisWoher die Namen kommen — Eselsbrücken zum Merken

Option kommt vom lateinischen optio, „freie Wahl“, verwandt mit optare, „wünschen, wählen“. Die drei Optionen hier schließen einander nicht aus; Sie wählen, was zu Ihrem Kurs passt, und können später wechseln.

ZIP geht auf das Programm PKZIP von Phil Katz zurück (1989). Ein Freund schlug den Namen vor, weil to zip im Englischen „flitzen“ heißt: Das Packen sollte schnell gehen. Das Bild vom Reißverschluss (zipper) passt trotzdem, denn eine ZIP-Datei ist ein Umzugskarton mit Reißverschluss. Alle Dateien samt Ordnerstruktur reisen darin in einem Stück und werden am Ziel genauso wieder ausgepackt.

Option 1 — Das ganze Skript als ZIP-Paket in Moodle

Das ist der Weg für alle, die mit der Workshop-Vorlage ein Skript gebaut haben und es ihren Studierenden im Moodle-Kurs zeigen wollen. Sie packen den Ordner docs/ in eine ZIP-Datei, laden sie als Material „Datei“ hoch, lassen Moodle sie auspacken und sagen Moodle, mit welcher Seite das Skript beginnt (Moodle, o. J.a; ZHAW Zürcher Hochschule für Angewandte Wissenschaften, o. J.).

Rechnen Sie beim ersten Mal mit zwanzig Minuten. Probieren Sie es zuerst in einem Testkurs aus. Viele Hochschulen stellen dafür eine Spielwiese bereit, oder Sie legen in Ihrem Kurs einen verborgenen Abschnitt an. Die Bezeichnungen der Schaltflächen können je nach Moodle-Version Ihrer Hochschule leicht abweichen.

Schritt 1 — Rendern

Öffnen Sie Ihr Projekt in RStudio (Doppelklick auf die .Rproj-Datei) und rendern Sie das ganze Skript: im Bereich Build auf Render Book oder mit Strg+Shift+B. Quarto schreibt die fertige Webseite in den Ordner docs/.

Prüfen Sie das Ergebnis, bevor Sie packen. Im Files-Bereich unten rechts öffnen Sie docs/, klicken auf index.html und wählen View in Web Browser. Was hier nicht funktioniert, funktioniert in Moodle auch nicht.

Schritt 2 — Das ZIP-Paket in RStudio erzeugen

Kopieren Sie die folgenden Zeilen in die Konsole von RStudio (das Fenster unten links, in dem > steht) und drücken Sie Enter:

# einmalig: install.packages("zip")
dateien <- list.files("docs", recursive = TRUE)
ziel    <- file.path(getwd(), paste0("fuer-moodle-", Sys.Date(), ".zip"))
zip::zip(ziel, files = dateien, root = "docs")

Die erste Zeile brauchen Sie nur beim allerersten Mal. Entfernen Sie dann das # am Anfang, damit R das Paket zip installiert. Ein Paket ist eine Erweiterung für R, so wie eine App für das Telefon. Die übrigen drei Zeilen tun Folgendes:

Was die Zeilen tun.
Zeile In einfachen Worten
dateien <- list.files(…) Schreibt eine Liste aller Dateien im Ordner docs/, auch in den Unterordnern.
ziel <- file.path(…) Legt fest, wie das Paket heißt und wo es liegt: im Projektordner, mit dem heutigen Datum im Namen, z. B. fuer-moodle-2026-11-16.zip.
zip::zip(…, root = "docs") Packt die Dateien so, dass index.html im Paket ganz oben liegt und nicht im Unterordner docs/.

Übernehmen Sie die Zeilen genau so, auch die Reihenfolge. Wer die Dateiliste direkt in die letzte Zeile schreibt, bekommt ein leeres Paket, weil R die Liste dann erst liest, nachdem es schon in den Ordner docs/ gewechselt ist.

Nach Enter erscheint die ZIP-Datei im Files-Bereich in Ihrem Projektordner. Ihre Größe liegt für die Workshop-Vorlage bei etwa einem halben Megabyte.

TippOhne Code: das ZIP mit dem Explorer packen
  1. Im Files-Bereich von RStudio den Ordner docs/ öffnen.
  2. Über das Zahnrad More → Show Folder in New Window den Ordner im Datei-Explorer (Windows) bzw. Finder (Mac) öffnen.
  3. Den Inhalt des Ordners markieren (Strg+A bzw. Cmd+A), nicht den Ordner selbst.
  4. Rechtsklick → In ZIP-Datei komprimieren (Windows 11) bzw. Senden an → ZIP-komprimierter Ordner (Windows 10) bzw. Komprimieren (Mac).

Der häufigste Fehler ist, den Ordner docs als Ganzes zu packen. Dann liegt index.html im Paket eine Ebene zu tief, und Moodle zeigt eine leere Seite.

WarnungDas ZIP gehört nicht ins Repository

Falls Sie zusätzlich mit GitHub arbeiten, tragen Sie die Zeile fuer-moodle-*.zip in die Datei .gitignore ein. Sonst lädt GitHub Desktop jedes Paket mit hoch.

Schritt 3 — Das Paket prüfen

Öffnen Sie die ZIP-Datei mit einem Doppelklick im Datei-Explorer. Ganz oben müssen index.html und die Ordner images, interactions und site_libs stehen. Sehen Sie dort nur einen Ordner docs, packen Sie neu.

Schritt 4 — In Moodle ein Material „Datei“ anlegen

  1. Öffnen Sie Ihren Kurs und schalten Sie oben rechts Bearbeiten ein.
  2. Klicken Sie im gewünschten Abschnitt auf Aktivität oder Material anlegen und wählen Sie Datei.
  3. Geben Sie einen Namen mit Datum ein, etwa „Skript Lehreinheit 1 (Stand 16.11.2026)“. Am Datum sehen Sie und Ihre Studierenden später auf einen Blick, welche Fassung online ist.
  4. Ziehen Sie die ZIP-Datei in das Feld Dateien auswählen.

Abkürzung: Sie können die ZIP-Datei auch direkt auf die Kursseite ziehen und Als Datei einbinden wählen (ZHAW Zürcher Hochschule für Angewandte Wissenschaften, o. J.). Die Einstellungen aus Schritt 5 und 6 öffnen Sie danach über Bearbeiten → Einstellungen bearbeiten.

Schritt 5 — Entpacken und Hauptdatei setzen

Noch liegt nur der verschlossene Karton in Moodle. Jetzt packen Sie ihn aus und zeigen Moodle die Eingangstür:

  1. Klicken Sie im Dateibereich auf das Symbol der ZIP-Datei und wählen Sie Entpacken. Moodle legt alle Dateien und Ordner aus dem Paket daneben ab.
  2. Die ZIP-Datei selbst können Sie danach anklicken und löschen; sie wird nicht mehr gebraucht.
  3. Klicken Sie auf index.html und wählen Sie Hauptdatei setzen. Der Dateiname erscheint dann fett (Moodle, o. J.a).

Die Hauptdatei ist die Startseite: die Seite, die Moodle öffnet, wenn jemand auf das Material klickt. Alle anderen Seiten erreichen Studierende über die Navigation des Skripts, weil Quarto die Verweise zwischen den Seiten relativ anlegt („die Seite nebenan“ statt einer vollständigen Webadresse).

Schritt 6 — Darstellung wählen und speichern

Unter Darstellung → Anzeigen stellen Sie ein, wie das Skript erscheint:

Anzeigeoptionen für das Material „Datei“.
Anzeige Was passiert Wann sinnvoll
Öffnen Das Skript füllt das ganze Browserfenster; die Moodle-Leisten verschwinden. Zurück geht es mit dem Zurück-Pfeil des Browsers. Empfehlung: Navigation und Inhaltsverzeichnis des Skripts haben vollen Platz, auch auf dem Tablet.
Einbetten Moodle zeigt seine Kopfzeile und darunter das Skript in einem Rahmen. wenn Studierende im Moodle-Rahmen bleiben sollen, eher am großen Bildschirm
Automatisch Moodle entscheidet selbst. wenn Sie nicht festlegen wollen

Die Optionen Im Frame und Neues Fenster sind in Moodle standardmäßig ausgeschaltet; ob sie bei Ihnen zur Wahl stehen, entscheidet die Administration (Moodle, o. J.b). Klicken Sie zum Schluss auf Speichern und anzeigen.

Schritt 7 — Mit den Augen der Studierenden prüfen

Wechseln Sie über Ihr Profilmenü mit Rolle wechseln → Studierende in die Ansicht der Lernenden und gehen Sie das Skript einmal durch:

  • Führt die Navigation links zu allen Seiten?
  • Erscheinen Bilder und Abbildungen?
  • Laufen die Lernspiele, und passt sich ihre Höhe an?
  • Findet die Suche oben ein Stichwort aus Ihrem Text?

Wenn alles funktioniert, ist Ihr Skript im Kurs. Sichtbar ist es nur für Personen, die in Ihren Kurs eingeschrieben sind.

Das Skript aktualisieren

Eine hochgeladene Fassung ist ein Schnappschuss: Ändern Sie das Skript in RStudio, ändert sich die Fassung in Moodle nicht von selbst. Für eine neue Fassung wiederholen Sie die Schritte 1 bis 3 und haben dann zwei Möglichkeiten:

  • Neues Material, altes weg. Sie legen ein zweites Material „Datei“ mit dem neuen Datum an und löschen oder verbergen das alte. Das ist der einfachste Weg.
  • Inhalt austauschen. Sie öffnen Einstellungen bearbeiten des bestehenden Materials, löschen im Dateibereich alle Einträge der alten Fassung (bei der unveränderten Vorlage sind es sieben: die drei .html-Seiten, search.json und die Ordner images, interactions und site_libs), laden das neue ZIP hoch, entpacken es und setzen index.html wieder als Hauptdatei. Diesen Weg nehmen Sie, wenn andere Stellen im Kurs auf genau dieses Material verweisen oder wenn Abschlussbedingungen daran hängen.

Passen Sie in beiden Fällen das Datum im Namen an.

Was dieser Weg kann und was nicht

Das Skript liegt auf dem Server Ihrer Hochschule und ist nur für eingeschriebene Studierende sichtbar. Damit eignet sich dieser Weg auch für internes Material wie Lösungen oder Musterfassungen, die Sie nach einer Sitzung freischalten (siehe Kapitel 12).

Moodle erfährt aber nur, dass jemand das Skript geöffnet hat, nicht, was die Person darin getan hat. Ergebnisse aus den Lernspielen landen nicht im Notenbuch. Die Selbsteinschätzungen der Vorlage speichert der Browser der jeweiligen Person, nicht Moodle. Wer Leistungen erfassen will, setzt einen kurzen Moodle-Test hinter das Skript (siehe Option 3 und Kapitel 13).

HinweisDatenschutz: eine Zeile für ganz ohne Fremdserver

Das Design cosmo der Vorlage lädt seine Schriftart beim Öffnen von Google Fonts. Damit fragt der Browser Ihrer Studierenden bei Google an, obwohl das Skript selbst in Moodle liegt. Eine Zeile im Abschnitt scss:defaults Ihrer styles.scss schaltet das ab; das Skript nutzt dann die Schrift des Betriebssystems:

$web-font-path: false;

Danach neu rendern und neu packen. Prüfen Sie auch Ihre Lernspiele: Laden sie Bibliotheken oder Schriften aus dem Netz, gilt dasselbe. Ein Spiel, das bei ausgeschaltetem WLAN läuft, braucht keine fremden Server.

Option 2 — Ein einzelnes Lernspiel direkt in Moodle

Nicht jede Lehrperson braucht ein ganzes Skript. Oft reicht ein einziges Lernspiel neben den Folien: ein Zuordnungsspiel zu den Grundbegriffen der Woche oder ein Quiz mit Rückmeldung. Das Spiel, das Sie in Block 1 mit der KI gebaut haben, ist bereits eine vollständige Webseite in einer einzigen HTML-Datei. Diese Datei können Sie ohne Quarto, ohne RStudio und ohne Paket direkt in Moodle stellen.

  1. Spiel speichern. Liegt das Spiel schon in Ihrem Ordner interactions/, nehmen Sie die Datei von dort. Kommt es frisch aus dem Chat, speichern Sie den Code in einer Datei mit der Endung .html, etwa begriffe-woche-03.html. In Claude oder ChatGPT gibt es dafür meist eine Schaltfläche zum Herunterladen.
  2. Offline testen. Schalten Sie WLAN aus und öffnen Sie die Datei per Doppelklick im Browser. Läuft das Spiel, braucht es keine fremden Server.
  3. In Moodle anlegen. Bearbeiten einschalten → Aktivität oder Material anlegen → Datei → Namen eingeben → HTML-Datei in Dateien auswählen ziehen.
  4. Anzeige wählen. Unter Darstellung wählen Sie Einbetten, damit das Spiel im Moodle-Rahmen erscheint, oder Öffnen für den vollen Bildschirm. Dann Speichern und anzeigen.

Lädt Moodle die Datei herunter, statt sie anzuzeigen, steht die Anzeige auf Download erzwingen; stellen Sie sie um.

Damit das Spiel diese Bedingungen erfüllt, hängen Sie an Ihren Spiel-Prompt einen Satz an:

Liefere das Spiel als eine einzige HTML-Datei: alle Stile, Skripte und Daten in der Datei selbst, keine externen Bibliotheken, Schriften oder Bilder aus dem Netz. Das Spiel muss offline laufen und in einem Lernmanagementsystem als hochgeladene Datei funktionieren.

Mehrere Spiele stellen Sie als mehrere Materialien „Datei“ in den Kurs. Werden es mehr als drei oder vier, lohnt sich Option 1: Dann bekommen die Spiele einen erklärenden Text, eine Reihenfolge und eine gemeinsame Navigation.

Option 3 — Buch und H5P: das Skript ganz in Moodle

Der dritte Weg verzichtet auf RStudio und Quarto ganz. Sie bauen das Skript mit Bordmitteln von Moodle: Den Text schreiben Sie in die Aktivität Buch, die Übungen bauen Sie mit H5P. H5P ist ein Baukasten für interaktive Übungen (Lückentext, Zuordnen, interaktives Video und vieles mehr), der in Moodle schon eingebaut ist. Kapitel 7 stellt die H5P-Inhaltstypen vor.

So entsteht ein Moodle-Skript:

  1. Buch anlegen. Aktivität oder Material anlegen → Buch. Jedes Kapitel des Buchs ist eine Seite mit Text, Bildern und Links; Moodle erzeugt das Inhaltsverzeichnis selbst.
  2. Übung im Inhaltsspeicher bauen. Der Inhaltsspeicher ist die Ablage für H5P-Inhalte in Ihrem Kurs; Sie finden ihn im Kursmenü unter Mehr. Dort klicken Sie auf Hinzufügen und wählen einen Inhaltstyp (Moodle, o. J.d).
  3. Übung ins Buch setzen. Im Texteditor eines Buchkapitels klicken Sie auf die Schaltfläche H5P, wählen über Repositories durchsuchen den Inhaltsspeicher und fügen die Übung mit H5P einfügen ein (Moodle, o. J.c).
  4. Bewertete Übungen. Soll eine Übung zählen, legen Sie sie zusätzlich als Aktivität H5P an. Dann trägt Moodle das Ergebnis ins Notenbuch ein (H5P Group, o. J.a).

Wer lieber alles in einem H5P-Inhalt hat, nimmt den Inhaltstyp Interactive Book: ein Buch mit mehreren Seiten, das interaktive Videos, Fragen und Präsentationen bündelt (H5P Group, o. J.b).

TippKI-first auch hier: Fragen per Import

Die KI schreibt Ihnen nicht nur Texte für die Buchkapitel, sondern auch Testfragen in einem Format, das Moodle direkt einlesen kann. GIFT ist ein einfaches Textformat für Moodle-Fragen; Sie lesen es über den Import der Fragensammlung ein. Ein Prompt dafür:

Schreibe zu folgendem Text [Text einfügen] fünf Multiple-Choice-Fragen im Moodle-GIFT-Format, je eine richtige und drei plausible falsche Antworten, mit kurzem Feedback zu jeder falschen Antwort. Gib nur den GIFT-Text aus.

Prüfen Sie jede Frage, bevor Sie sie freischalten. Die KI erfindet gelegentlich falsche Antworten, die in Wahrheit richtig sind.

Dieser Weg passt, wenn Sie Bewertungen im Notenbuch brauchen oder wenn Ihnen jede Installation zu viel ist. Er hat zwei Nachteile. Sie klicken Übungen im Editor zusammen, statt sie von der KI frei gestalten zu lassen, und das Skript lebt nur in diesem einen Moodle-Kurs. Ihre eigenen KI-Lernspiele fügen Sie hier nur als zusätzliches Material „Datei“ (Option 2) neben das Buch, nicht in das Buch hinein. Welche H5P-Inhaltstypen zur Verfügung stehen, legt zudem jede Hochschule selbst fest.

Welche Option für wen?

Die Wahl hängt weniger an der Technik als an der Frage, was Ihr Kurs braucht. Wer mit der Workshop-Vorlage ein Skript gebaut hat, nimmt Option 1. Wer nur ein Spiel braucht, nimmt Option 2. Wer Ergebnisse im Notenbuch sehen muss oder ohne jede Installation arbeiten will, nimmt Option 3. Später können Sie jederzeit zu Kapitel 9 wechseln, wenn Sie Ihr Skript zusätzlich öffentlich teilen wollen. Das ZIP aus Option 1 und die Webseite auf GitHub Pages entstehen aus demselben Ordner docs/.

WarnungWas, wenn …
  • Moodle zeigt eine leere Seite statt des Skripts? → index.html liegt im Paket in einem Unterordner, oder die Hauptdatei ist nicht gesetzt. Paket wie in Schritt 2 neu erzeugen, in Schritt 5 index.html als Hauptdatei setzen.
  • Das ZIP ist leer oder enthält nur wenige Kilobyte? → Die Dateiliste wurde nicht vorab in dateien gespeichert. Die drei Zeilen aus Schritt 2 genau so übernehmen.
  • Moodle lädt das Skript herunter, statt es anzuzeigen? → Unter Darstellung → Anzeigen von „Download erzwingen“ auf „Öffnen“ umstellen.
  • Der Upload bricht ab? → Das Paket ist größer als das Limit Ihrer Moodle-Installation; die Grenze steht im Feld Dateien auswählen. Große Videos gehören nicht ins Skript, sondern auf die Videoplattform Ihrer Hochschule und werden verlinkt.
  • Spiele oder Suche laufen in Moodle nicht, lokal aber schon? → Manche Installationen beschränken JavaScript in hochgeladenen Dateien. Fragen Sie die Moodle-Administration Ihrer Hochschule; bis dahin hilft ein Link auf eine öffentliche Fassung (Kapitel 9).
  • Die Studierenden sehen noch die alte Fassung? → Datum im Namen prüfen; eventuell wurde das neue Paket entpackt, aber index.html nicht wieder als Hauptdatei gesetzt.
