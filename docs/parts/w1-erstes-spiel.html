Block 1 — Das erste Spiel: von der Begriffsliste zum Memory

45 Minuten · Vorlage öffnen, Begriffe sammeln, Spiel bauen, einbauen

Was Sie nach diesem Block können

  • die Starter-Vorlage öffnen, rendern und die vier wichtigen Stellen darin finden;
  • mit KI in zehn Minuten eine geprüfte Liste von Grundbegriffen Ihres Fachs erstellen;
  • daraus ein Memory-Spiel bauen lassen und es in Ihre Lehreinheit einbauen.

Worum es im Kern geht

In diesem Block schreiben Sie keine Zeile Code. Die KI baut das Spiel, die Vorlage hat den Platz dafür schon reserviert, und Sie tauschen eine Datei aus. Nach 45 Minuten läuft in Ihrer eigenen Lehreinheit ein Spiel mit Ihren Fachbegriffen. Die Arbeit, die bleibt, ist die eigentlich didaktische: prüfen, ob die Begriffe stimmen und die Definitionen sich nicht gegenseitig verraten.

Setup-Check: Läuft die Vorlage? (5 min)

Wer in Teil 0 den Selbsttest bestanden hat, hat die Vorlage schon einmal gerendert. Alle anderen holen das jetzt nach:

  1. Starter-Vorlage herunterladen (ZIP) und entpacken, am besten in einen Ordner ohne Leerzeichen und Umlaute im Pfad, etwa Dokumente/skripte/.
  2. In RStudio File → Open Project… → starter-lehreinheit.Rproj wählen.
  3. Im Reiter Terminal eingeben: quarto preview

Im Browser erscheint eine Lehreinheit „Lernen mit Tests“ mit Vorab-Check, Memory, Zuordnungsspiel und Lern-Check. Die Vorschau bleibt offen und aktualisiert sich bei jedem Speichern.

Rundgang: vier Stellen (5 min)

Ein Quarto-Projekt ist wie ein Setzkasten in einer Druckerei: Jede Sorte Teil hat ihr Fach, und der Setzer greift blind hinein. Sie müssen nur vier Fächer kennen.

Alles andere ist fertig eingerichtet. Die Datei PROMPTS.md enthält alle Prompts dieses Workshops zum Kopieren.

Schritt 1 — Grundbegriffe per Multiple Choice sammeln (10 min)

Die KI fragt Sie viermal per Multiple Choice nach Fach, Quelle, Niveau und Anzahl und baut daraus eine Tabelle. Sie tippen also kaum, sondern wählen. Haben Sie Vorlesungsfolien oder ein Skriptkapitel, wählen Sie bei der Quellenfrage die eigene Quelle: Dann kommen nur Begriffe vor, die Ihre Studierenden auch im Material finden.

  • Chat (jede KI)
  • Agent (Claude Desktop, Codex)

Neuen Chat öffnen, Prompt einfügen, abschicken. Bei der Quellenfrage die Datei hochladen oder den Text einfügen.

Sie helfen mir, die Grundbegriffe für eine Lehreinheit zusammenzustellen. Stellen Sie mir zuerst nacheinander vier Fragen, jede als Multiple Choice mit den Optionen a) bis d) und „e) eigene Angabe“. Warten Sie nach jeder Frage auf meine Antwort.

1. Fach und Thema der Einheit. Wenn ich nur das Fach nenne, schlagen Sie vier typische Themen vor.
2. Woher kommen die Begriffe? a) aus einer Quelle, die ich gleich einfüge oder hochlade; b) aus Ihrem Wissen; c) Ihre Vorschläge, abgeglichen mit meiner Quelle; d) aus meinem Vorlesungsskript als Datei.
3. Niveau: a) erstes Semester; b) fortgeschrittenes Bachelorstudium; c) Master; d) Weiterbildung.
4. Anzahl der Begriffe: a) 6; b) 8; c) 10; d) 12.

Danach erstellen Sie eine Tabelle mit den Spalten: Begriff | Definition | typische Verwechslung | Fundstelle.

Regeln:
- Definitionen in eigenen Worten, höchstens 15 Wörter, ohne den Begriff selbst zu wiederholen.
- Kein Begriff steckt in der Definition eines anderen, sonst verrät das Spiel die Lösung.
- Mit Quelle: nur Begriffe, die in der Quelle vorkommen; Fundstelle mit Seite oder Abschnitt.
- Ohne Quelle: In der Spalte Fundstelle steht „bitte prüfen“. Nennen Sie kein Lehrbuch, das Sie nicht sicher kennen.

Fragen Sie zum Schluss, ob ich Begriffe tauschen, kürzen oder ergänzen will.

Den Ordner der Starter-Vorlage verbinden (in Claude Desktop: Ordner auswählen). Eigene Quellen vorher nach material/ legen.

Im verbundenen Ordner liegt meine Starter-Vorlage für ein Quarto-Skript. Ich möchte die Grundbegriffe für meine Lehreinheit zusammenstellen.

Stellen Sie mir zuerst nacheinander vier Fragen als Multiple Choice (a bis d, dazu „eigene Angabe“) und warten Sie jeweils auf meine Antwort:
1. Fach und Thema der Einheit (bei bloßer Fachangabe: vier typische Themen vorschlagen);
2. Quelle der Begriffe: a) eine Datei, die ich in den Ordner material/ lege; b) Ihr Wissen; c) beides abgeglichen; d) eine Webseite, deren Adresse ich nenne;
3. Niveau: a) erstes Semester; b) fortgeschrittenes Bachelorstudium; c) Master; d) Weiterbildung;
4. Anzahl: a) 6; b) 8; c) 10; d) 12.

Legen Sie danach die Datei begriffe.md im Projektordner an, mit einer Tabelle: Begriff | Definition | typische Verwechslung | Fundstelle.
Regeln: Definitionen in eigenen Worten, höchstens 15 Wörter, ohne den Begriff selbst; kein Begriff steckt in einer anderen Definition; mit Quelle nur Begriffe aus der Quelle samt Seite oder Abschnitt; ohne Quelle steht bei Fundstelle „bitte prüfen“.
Ändern Sie keine anderen Dateien. Zeigen Sie mir die Tabelle und fragen Sie, ob ich etwas tauschen will.

Prüfen, bevor es weitergeht (Discernment): Lesen Sie jede Definition einmal so, wie es eine Studentin im ersten Semester täte. Stimmt sie fachlich? Verrät sie einen anderen Begriff? Steht bei Fundstelle „bitte prüfen“, haben Sie die Prüfung noch vor sich.

Schritt 2 — Das Memory bauen lassen (10 min)

Der Prompt bestellt das Spiel wie einen Werkvertrag: Ziel, Material und die Kriterien, an denen Sie es abnehmen. Die technischen Kriterien sorgen dafür, dass das Spiel ohne Internet läuft, mit der Tastatur bedienbar ist und seine Höhe selbst an die Seite meldet, damit nichts abgeschnitten wird.

  • Chat (jede KI)
  • Agent (Claude Desktop, Codex)

Im selben Chat wie Schritt 1 weiterschreiben, damit die KI die Tabelle kennt.

Bauen Sie aus der Tabelle oben ein Memory-Spiel.
Ziel: Lernende decken je zwei Karten auf und finden zu jedem Begriff die passende Definition. Bei jedem gefundenen Paar erscheint die Definition noch einmal ganz; am Ende stehen die Zahl der Versuche und ein Knopf „Neu mischen“.

Technische Abnahmekriterien:
- Eine einzige HTML-Datei, kein externer Code, keine Bilder oder Schriften aus dem Netz. Sie muss offline und eingebettet in einem iframe laufen.
- Alle Inhalte stehen oben in einem Block `const DATEN = { … };` zwischen den Kommentaren /* ===== DATEN: Nur diesen Block ändern ===== */ und /* ===== ENDE DATEN ===== */. Der Programmcode darunter liest nur aus DATEN.
- Alles Klickbare ist ein <button> und mit der Tastatur bedienbar; Rückmeldungen stehen in einem Bereich mit aria-live="polite".
- Auf einem Handy (360 px Breite) gut bedienbar, ohne seitliches Scrollen.
- Die Datei meldet ihre Höhe an die einbettende Seite: window.parent.postMessage({typ: "iframe-hoehe", hoehe: document.documentElement.scrollHeight}, "*") nach dem Laden, bei Größenänderung und nach jeder Antwort.
- Oberfläche auf Deutsch in der Sie-Form, sachlich, ohne Konfetti, Sounds oder dekorative Animationen.
- Jede Rückmeldung erklärt in einem Satz, warum eine Antwort stimmt oder nicht.

Geben Sie nur den vollständigen Code in einem einzigen Codeblock aus.

Der Agent speichert das Spiel selbst und rendert danach. Sie können Schritt 3 überspringen.

Bauen Sie aus der Tabelle in begriffe.md ein Memory-Spiel.

Arbeitsschritte:
1. Speichern Sie das Spiel als interactions/spiel-01.html (die vorhandene Beispieldatei wird ersetzt).
2. Passen Sie in lehreinheit.qmd im ersten Abschnitt nur den Titel des Kastens „Lernspiel: …“ und den Satz darunter an. Die iframe-Zeile bleibt, wie sie ist.
3. Rendern Sie mit `quarto render` und melden Sie mir Fehler oder Warnungen in einfachen Worten.
Ändern Sie keine anderen Dateien.

Schritt 3 — Einbauen und rendern (10 min, nur Chat-Weg)

  1. Den Code aus der Antwort der KI kopieren (Knopf Copy oben rechts am Codeblock).
  2. In RStudio unten rechts im Reiter Files den Ordner interactions/ öffnen und auf spiel-01.html klicken. Die Datei öffnet sich im Editor.
  3. Alles markieren (Strg+A), den neuen Code einfügen (Strg+V), speichern (Strg+S).
  4. Die Vorschau im Browser lädt neu. Ihr Memory steht jetzt im ersten Abschnitt.
  5. In lehreinheit.qmd den Titel des Kastens „Lernspiel: …“ an Ihr Thema anpassen.

Das ist der Kern des ganzen Workshops: Die Vorlage hält einen Platz frei, die KI liefert die Datei, Sie tauschen sie aus. Die iFrame-Zeile im Text, also das Fenster, durch das das Spiel in die Seite scheint, fassen Sie nie an.

Variieren Sie

  • Memory zur Syntax: Lassen Sie ein zweites Memory mit Paaren aus Quarto-Schreibweise und Wirkung bauen, etwa **fett** ↔︎ „Text erscheint fett“ oder @fig-abb-01 ↔︎ „Verweis auf Abbildung 1“. So üben Sie und Ihre Kolleginnen die Syntax, die Sie gleich brauchen.
  • Nur die Inhalte tauschen: Öffnen Sie spiel-01.html und ändern Sie im Block zwischen DATEN und ENDE DATEN ein Begriffspaar von Hand. Speichern, Vorschau ansehen.
  • Anderer Spieltyp, gleiche Tabelle: „Bauen Sie aus derselben Tabelle einen Lückentext statt eines Memorys.“ Die technischen Kriterien bleiben gleich.

Was, wenn …

WarnungWas, wenn …
  • die Antwort der KI mitten im Code abbricht? → „Bitte geben Sie die vollständige Datei noch einmal in einem einzigen Codeblock aus.“ Teilstücke nicht zusammenkleben.
  • das Spiel leer bleibt? → Die Datei im Browser direkt öffnen (Doppelklick auf spiel-01.html). Bleibt sie leer, der KI schreiben: „Die Datei zeigt im Browser nichts an. Bitte prüfen und korrigieren.“
  • unter Windows eine Datei spiel-01.html.txt entsteht? → Im Explorer Ansicht → Dateinamenerweiterungen einschalten und .txt entfernen. Mit dem Weg über RStudio (Schritt 3) passiert das nicht.
  • das Spiel abgeschnitten ist? → Die KI hat die Höhenmeldung vergessen. Nachschieben: „Ergänzen Sie die Höhenmeldung per postMessage wie in den Abnahmekriterien.“
  • quarto preview meldet „port already in use“? → Es läuft noch eine Vorschau. Im Terminal Strg+C, dann neu starten.
